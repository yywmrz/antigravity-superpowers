# /tdd 工作流

当用户输入 `/tdd` 时，启动测试驱动开发流程。

## 触发条件
- 用户输入 `/tdd`
- 开始编写新功能或修复 bug 时

## 执行步骤

### 1. 明确目标
询问用户：
- "要实现什么功能？"
- "期望的行为是什么？"
- "有哪些边界情况？"

### 2. RED 阶段
编写失败的测试：
```
1. 明确要测试的行为
2. 编写测试代码
3. 运行测试，确认失败
4. 确认失败原因是功能未实现
```

### 3. GREEN 阶段
编写最少代码通过测试：
```
1. 写最简单的实现
2. 不要过度设计
3. 运行测试，确认通过
4. 立即提交
```

### 4. REFACTOR 阶段
重构代码：
```
1. 检查重复代码
2. 改善命名
3. 简化结构
4. 运行测试确认没破坏
5. 提交重构
```

### 5. 循环
重复 RED-GREEN-REFACTOR 直到功能完成。

## 反模式警告
- ❌ 先写代码再补测试
- ❌ 一次写太多测试
- ❌ 测试通过前就重构
- ❌ 跳过失败验证步骤

## 完成标志
- [ ] 测试已编写
- [ ] 测试曾经失败
- [ ] 代码已实现
- [ ] 测试现在通过
- [ ] 代码已重构
