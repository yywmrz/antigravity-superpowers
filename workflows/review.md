# /review 工作流

当用户输入 `/review` 时，启动代码审查流程。

## 触发条件
- 用户输入 `/review`
- 提交代码前自我审查
- 审查他人 PR

## 执行步骤

### 1. 确定范围
询问用户：
- "要审查哪些文件/变更？"
- "这次变更的目的是什么？"

### 2. 正确性检查
- [ ] 代码是否实现预期功能？
- [ ] 逻辑是否正确？
- [ ] 有没有明显 bug？

### 3. 边界情况检查
- [ ] 空值处理是否正确？
- [ ] 错误条件是否处理？
- [ ] 并发情况是否考虑？
- [ ] 极端输入是否处理？

### 4. 代码风格检查
- [ ] 是否遵循项目规范？
- [ ] 命名是否清晰？
- [ ] 注释是否有帮助？
- [ ] 结构是否清晰？

### 5. 性能检查
- [ ] 有没有性能问题？
- [ ] 是否有不必要的循环？
- [ ] 数据库查询是否优化？

### 6. 安全检查
- [ ] 输入是否验证？
- [ ] 敏感数据是否保护？
- [ ] 是否有注入风险？

### 7. 输出反馈
按严重程度分类：
```
**[必须]** 问题: xxx | 原因: xxx | 建议: xxx
**[建议]** 问题: xxx | 原因: xxx | 建议: xxx
**[备注]** 信息: xxx
```

## 完成标志
- [ ] 正确性已检查
- [ ] 边界情况已检查
- [ ] 代码风格已检查
- [ ] 性能已检查
- [ ] 安全已检查
- [ ] 反馈已输出
