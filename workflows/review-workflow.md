# 代码审查工作流

## 使用场景
- 审查他人提交的 PR
- 提交前自我审查
- 代码质量检查

## 工作流程

### 1. 了解上下文
- 阅读 PR 描述
- 了解变更目的
- 查看关联的 issue

### 2. 高层审查
- 变更是否符合设计？
- 是否有更简单的方案？
- 是否遵循项目架构？

### 3. 详细审查
使用 `code-review` 技能检查：

#### 正确性
- 逻辑是否正确？
- 是否实现了预期功能？

#### 边界情况
- 空值处理
- 错误处理
- 并发情况
- 极端输入

#### 代码风格
- 命名清晰
- 结构合理
- 注释适当

#### 性能
- 无明显性能问题
- 查询优化
- 无内存泄漏

#### 安全性
- 输入验证
- 敏感数据保护
- 无注入风险

### 4. 提供反馈
按模板提供反馈：
```
**[严重程度: 必须/建议/备注]**

问题: [具体描述]
原因: [为什么这是问题]
建议: [如何修改]
```

### 5. 跟进
- 确认作者理解反馈
- 验证修改是否正确
- 批准或请求更多修改

## 审查清单
- [ ] 变更目的明确
- [ ] 代码逻辑正确
- [ ] 边界情况处理
- [ ] 有测试覆盖
- [ ] 无安全问题
- [ ] 文档已更新
