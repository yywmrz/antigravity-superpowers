# /writing-plans 工作流

当用户输入 `/writing-plans` 时，开始编写实施计划。

## 触发条件
- 用户输入 `/writing-plans`
- 设计方案已确定后

## 执行步骤

### 1. 确认设计
检查是否有已批准的设计文档：
- 如果有，基于设计文档创建计划
- 如果没有，先运行 `/brainstorming`

### 2. 任务拆分
将工作拆分成原子任务：
- 每个任务 2-5 分钟完成
- 每个任务包含精确的文件路径
- 每个任务包含完整代码片段
- 每个任务包含验证步骤

### 3. 排序依赖
- 识别任务间的依赖关系
- 确保依赖任务排在前面
- 标记可并行执行的任务

### 4. 输出计划
生成实施计划，每个任务格式：
```markdown
## Task [N]: [简短描述]

### 目标
[任务目标]

### 变更
- `[文件路径]`: [具体改动]

### 代码
```[语言]
[完整代码]
```

### 验证
1. [验证步骤]

### 完成标志
- [ ] 代码已修改
- [ ] 测试通过
```

### 5. 请求批准
展示计划给用户，等待批准后再执行。

## 完成标志
- [ ] 任务已拆分
- [ ] 依赖已排序
- [ ] 计划已输出
- [ ] 用户已批准
