# /debug 工作流

当用户输入 `/debug` 时，启动系统性调试流程。

## 触发条件
- 用户输入 `/debug`
- 遇到 bug 或异常行为时

## 执行步骤

### 1. 收集信息
询问用户：
- "问题是什么？"
- "如何复现？"
- "什么时候开始出现的？"
- "有错误信息吗？"

### 2. 阶段1: 收集证据
- 复现问题
- 收集错误消息
- 收集堆栈跟踪
- 检查最近变更

### 3. 阶段2: 形成假设
列出可能的原因：
```
假设 1: [原因]
  证据: [支持证据]
  验证: [如何验证]

假设 2: [原因]
  证据: [支持证据]
  验证: [如何验证]
```

### 4. 阶段3: 验证假设
从最可能的假设开始：
- 执行验证步骤
- 记录结果
- 确认或排除
- 继续下一个假设

### 5. 阶段4: 修复验证
- 实施修复
- 验证问题已解决
- 确认没有新问题
- 添加防护测试

## 调试技巧
- 使用二分法定位问题
- 添加调试日志
- 一次只改一个变量

## 完成标志
- [ ] 问题已复现
- [ ] 根因已定位
- [ ] 修复已实施
- [ ] 修复已验证
- [ ] 防护测试已添加
