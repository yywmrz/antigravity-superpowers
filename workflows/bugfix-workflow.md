# Bug 修复工作流

## 使用场景
- 用户报告了一个 bug
- 发现代码行为异常
- 需要排查和修复问题

## 工作流程

// turbo-all

### 1. 问题收集
收集问题相关信息：
- 复现步骤
- 错误信息
- 期望行为 vs 实际行为
- 首次出现时间

### 2. 系统性调试
使用 `systematic-debugging` 技能：

#### 阶段1: 收集证据
- 复现问题
- 收集日志
- 检查最近变更

#### 阶段2: 形成假设
- 列出可能原因
- 按可能性排序
- 设计验证方法

#### 阶段3: 验证假设
- 执行验证
- 记录结果
- 确认或排除

#### 阶段4: 定位问题
- 确定根因
- 记录发现

### 3. 测试驱动修复
使用 `test-driven-development` 技能：
- 先写一个能复现 bug 的测试
- 确认测试失败
- 修复代码
- 确认测试通过

### 4. 验证修复
使用 `verification-before-completion` 技能：
- 确认原始问题已解决
- 确认没有引入新问题
- 确认相关功能正常

### 5. 添加防护
- 添加防止回归的测试
- 更新相关文档
- 提交变更

## 检查点
- [ ] 问题已复现
- [ ] 根因已定位
- [ ] 回归测试已添加
- [ ] 修复已验证
- [ ] 变更已提交
