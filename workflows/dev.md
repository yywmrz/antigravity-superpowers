# 开发工作流

## 使用场景
- 开始一个新功能的开发
- 实现用户提出的新需求

## 工作流程

// turbo-all

### 1. 需求澄清
使用 `brainstorming` 技能进行需求澄清：
- 理解用户真正想要什么
- 提出澄清问题
- 探索可选方案
- 输出设计文档供用户确认

### 2. 制定计划
使用 `writing-plans` 技能制定实施计划：
- 将工作拆分成 2-5 分钟的小任务
- 每个任务包含精确的文件路径和代码
- 标明验证步骤
- 请求用户批准计划

### 3. 测试驱动实施
使用 `test-driven-development` 技能编写代码：
- 先写失败的测试 (RED)
- 写最少的代码让测试通过 (GREEN)
- 重构代码 (REFACTOR)
- 提交变更

### 4. 代码审查
使用 `code-review` 技能自我审查：
- 检查正确性
- 检查边界情况
- 检查代码风格
- 检查性能问题

### 5. 完成验证
使用 `verification-before-completion` 技能验证：
- 功能验证
- 回归验证
- 集成验证
- 更新文档

## 检查点
- [ ] 设计文档已批准
- [ ] 实施计划已批准
- [ ] 所有测试通过
- [ ] 代码审查通过
- [ ] 最终验证通过
