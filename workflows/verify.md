# /verify 工作流

当用户输入 `/verify` 时，启动完成前验证流程。

## 触发条件
- 用户输入 `/verify`
- 宣布任务完成之前

## 执行步骤

### 1. 功能验证
- [ ] 主要功能是否工作？
- [ ] 边界情况是否处理？
- [ ] 错误情况是否正确处理？

### 2. 回归验证
运行测试套件：
```bash
npm test  # 或项目对应的测试命令
```
- [ ] 所有测试通过？
- [ ] 没有新的警告？
- [ ] 相关功能正常？

### 3. 集成验证
- [ ] 与其他组件交互正常？
- [ ] API 契约保持一致？
- [ ] 数据库迁移成功？

### 4. 文档验证
- [ ] README 是否需要更新？
- [ ] API 文档是否需要更新？
- [ ] 变更日志是否更新？

### 5. 生成验证报告
输出验证报告：
```markdown
## 验证报告

### 功能测试
- 测试项: [描述]
- 结果: ✅ 通过 / ❌ 失败
- 证据: [截图/日志]

### 回归测试
- 命令: `npm test`
- 结果: X/Y 测试通过

### 手动验证
- 场景: [描述]
- 结果: [描述]

### 结论
[✅ 验证通过，可以发布] 或 [❌ 发现问题，需要修复]
```

## 常见陷阱
- ❌ 只在本地测试
- ❌ 只测试正常情况
- ❌ 依赖缓存旧状态
- ❌ 没有清理测试数据

## 完成标志
- [ ] 功能验证通过
- [ ] 回归验证通过
- [ ] 集成验证通过
- [ ] 文档已更新
- [ ] 验证报告已生成
