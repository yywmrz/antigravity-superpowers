# 测试驱动开发技能

严格遵循 TDD 的 RED-GREEN-REFACTOR 循环。

## 核心原则
1. **永远先写测试** - 没有失败的测试就不写生产代码
2. **最小实现** - 只写让测试通过的最少代码
3. **持续重构** - 测试通过后立即重构

## 工作流程

### RED 阶段（红灯）
1. 明确要实现的行为
2. 编写一个描述该行为的测试
3. 运行测试，确认它失败
4. 确认失败原因是功能未实现，不是测试本身的问题

### GREEN 阶段（绿灯）
1. 写最简单的代码让测试通过
2. 不要过度设计
3. 运行测试，确认通过
4. 立即提交

### REFACTOR 阶段（重构）
1. 检查代码是否有重复
2. 检查命名是否清晰
3. 检查是否遵循单一职责
4. 运行测试确认没有破坏功能
5. 提交重构

## 反模式警告
避免以下行为：
- ❌ 先写代码再补测试
- ❌ 一次性写太多测试
- ❌ 测试通过前就开始重构
- ❌ 跳过失败测试的验证步骤

## 测试命名规范
```
test_[被测功能]_[场景]_[期望结果]
```

示例：
- `test_login_with_valid_credentials_returns_token`
- `test_login_with_invalid_password_returns_401`
